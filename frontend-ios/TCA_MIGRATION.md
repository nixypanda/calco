## Destination architecture (whole-app TCA)

- Destination is **actual TCA reducers/features**, not ObservableObject/ViewModel wrappers around legacy VMs.
- Use `swift-composable-architecture` as the sole architecture dependency choice. TCA transitives resolved by SPM are acceptable; already-resolved transitive packages may be explicitly declared and linked when direct generated-symbol references require it (for example `Dependencies`/`CasePaths`, and `Clocks` 1.1.1 for `CalCoTests` only where `TestClock` symbols are referenced), but do not add unrelated libraries or hand-maintain an unnecessary transitive list in this doc.
- App shape should be explicit TCA composition:
  - **App/session scope:** authentication/bootstrap/session generation, signed-in account boundary, global session invalidation/reset.
  - **Window/shell scope:** per-window/per-scene navigation, selected date/meal-slot context, tab/path state, transient UI presentation. Window state must not outlive or leak across session/account boundaries.
  - **Service placement:** API clients, adapters, and service protocols belong in TCA `DependencyValues` (overridden in `TestStore`), never in feature `State`. State holds domain data plus lifecycle and request identity only.
- **State modeling rules:**
  - Use **enum payloads** for dependent lifecycle state (loading/loaded/failed/submitting/deleting/confirming) where variants are mutually exclusive.
  - Use **independent sibling machines/state slices** when states are valid independently (e.g., independent sections/panes/requests whose data can load/fail separately).
  - **Retained native UX delta (deliberate, not web parity):** keep **visible search results on screen during a refresh/in-flight query** instead of clearing them as `src/Page/Food/Search.elm` does in `applyQueryChange`. The approved preceding plan retains this native behavior; do not remove it in the name of parity. Model it in the reducer state, never as an independent `isRefreshing` boolean beside a `results` field: the active lifecycle case carries the prior valid results explicitly (for example `.loaded(results, refresh: .inFlight(query, token))` or `.refreshing(previous: Results, query, token)`), and stale/duplicate completions are rejected by token.
- **Cache is not the TCA `Store`:** the TCA `Store` is the state container; it does not replace the web cache. Port `src/Store.elm` as a separate cache dependency/slice with opaque request tokens (session generation + request id), at most one in-flight request per resource, cached failures, and token-only `settle`/`invalidate`/`seed`. Bump the cache generation on session change; after every log mutation invalidate that date's logs **and all dates' latest-slot suggestions** (the 30-day lookback makes the changed date a source for any date), and refresh diary/calendar panes explicitly rather than relying on navigation re-init.
- **Action ownership:** child features emit **delegate actions** for parent-owned effects/navigation/session transitions; parents own cross-feature coordination. Avoid child features directly mutating unrelated parent/global state.
- **No new replay/journal behavior:** legacy journal/submission persistence is **frozen** — every existing invariant stays regardless of which tests are retained or retired. Do not add new replay, durable intent ledgers, automatic retry/replay, or idempotency infrastructure during migration, and do not let a new write path depend on the legacy journal. Frozen invariants include account-scoped storage; schema-versioned envelope with quarantine and fail-closed unreadable accounts; bounded entries and body size; byte-frozen request body and timezone; the `inFlight/uncertain/succeeded/rejected/conflicted/invalidated` state machine; terminal non-retryable `invalidated` records; retry barriers installed before persistence; and one process-wide store. Test-retention decisions never authorize weakening these.
